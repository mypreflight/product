# Frontend standards

How MyPreflight's frontend is built and how new code should be written.

Last reviewed: 2026-10-20

Covers the web app (`app` in `../../repos.md`) and the website (`landing`). Visual rules are in `design-rules.md`; repo-specific commands stay in each repo's `CLAUDE.md`.

## Web app: stack

| Concern | Choice |
| --- | --- |
| Framework | React 19 with React Router (framework config, `ssr: false`): a static SPA with no server of its own |
| Build | Vite, TypeScript strict, Node 26 |
| UI | Flowbite React, heavily extended through one theme file; Tailwind CSS v4 configured with `@theme` in `app/styles/index.css` (no `tailwind.config`) |
| Forms | Formik with Yup schemas |
| Maps | Leaflet through react-leaflet, CARTO raster basemaps |
| Charts | Recharts |
| Live updates | socket.io-client on the API's flight event stream |
| PWA | `vite-plugin-pwa`, prompt-to-reload on a new version |
| Lint and format | Biome: 2-space indent, 120-character lines, double quotes |
| Language | English only. Enum labels go through `toHuman` (`app/i18n/translate.ts`) and each slice's `i18n.ts` |

## Structure

Code is sliced by domain, not by technical layer: `app/features/<domain>/`. A slice uses only what it needs:

```text
components/      feature-owned React components
hooks/           feature-scoped hooks and context providers
lib/             pure helpers
model.ts(x)      types, enums and domain classes
service.ts       API service class
schema.ts        Yup schemas
form.ts          Formik initial values and form types
request.ts       request payload types
transformer.ts   model <-> request mapping
i18n.ts          enum-to-label translators
index.ts         barrel export
```

- Cross-feature building blocks live in `app/shared/` (`api/`, `ui/`, `hooks/`, `lib/`, `models/`, `validator/`, `pwa/`).
- Global state lives in `app/app-state/`. `app/components/` holds only the public landing page.
- Import with the `~/` alias for `app/`.

## Routing

- Routes are declared in `app/routes.ts` with React Router's `layout()`, `route()` and `index()`.
- Layouts carry the access rules:

  | Layout | Covers |
  | --- | --- |
  | `AuthLayout` | Sign-in, sign-out, email confirmation, the Discord callback |
  | `MapLayout` | The public map; no sign-in |
  | `AppLayout` | Everything signed in; wraps `AuthGuard` |
  | `PilotLayout` | Pilot (CabinCrew) screens |
  | `OperationsLayout` | Operations screens |
  | `ReviewLayout` | The data-change review queue, for Operations and Admin |

- `AuthGuard` takes `allowOnly` (one role or a list).
- Route modules are the only default exports.

## Data and state

- Each slice has a service class extending `AbstractApiService` (public) or `AbstractAuthorizedApiService` (bearer auth).
- The authorized services come from `useApi()`, instantiated once in a provider. The public map uses `usePublicApi()` singletons.
- Tokens refresh proactively (30 s before expiry) and reactively (one retry after a `401`).
- A 4xx rejects with `ErrorResponse`, whose `violations` map feeds field-level form errors.
- All state is React Context. No Redux, no Zustand. `useLocalStorage()` is for per-browser conveniences such as pinned airports and map settings.

## Components

- Named exports; PascalCase files and folders.
- Use the managed form blocks in `app/shared/ui/Form/Managed/` instead of raw Flowbite inputs.
- Style Flowbite through `app/styles/theme.ts` (`createTheme`), never per-call class hacks or `data-testid` selectors.
- Domain types live in each slice's `model.ts`; a few are classes (e.g. `Flight`) that parse API responses.

## Code style

- No comments in code: no explanations, section headers, JSDoc, TODOs or `biome-ignore`. If code seems to need one, rename or restructure it.

## Integrations

- Google and Discord sign-in are optional per build. Without their client IDs every Google or Discord surface disappears and the app runs on email and password alone.
- Discord OAuth is a full-page redirect. Its deep link reaches the router through a static-hosting rewrite (`public/404.html` plus `public/ghspa.js`) that exists only in a built app, so test that flow on a build.
- Absolute URLs (the Discord redirect, map share links) come from `window.location.origin`. Nothing hardcodes the domain.
- Four things outside the repo are tied to the app's origin and must change together if it ever moves:
  1. DNS.
  2. The API's CORS allow-list.
  3. The Discord redirect URI.
  4. The Google authorized origin.

## Maps

- Basemaps stay on CARTO's raster tiles. Vector tiles were evaluated and rejected: free vector sources stop at zoom 14, too low for aprons, stands and gates. Revisit only when a vector source serves detail above zoom 14.
- Map element styling follows `design-rules.md` → Maps.

## PWA

- Icons and the 88 iOS splash images are generated by a script, never edited by hand. The splash is a pixel copy of the in-app splash, so launch shows no flash.
- A new iOS device needs a new entry in the device list plus a regeneration.

## Testing and CI

- No unit test framework is configured.
- Pull requests run a version check, lint, typecheck and build.
- The version in `package.json` must be bumped before merging; CI fails otherwise.
- A push to `main` builds, tags the version, creates a GitHub release and deploys to GitHub Pages.
- The dev server mounts routes twice, so API calls fire about twice. Check network volume on a build, not in dev.

## Website (landing)

| Concern | Rule |
| --- | --- |
| Framework | Astro, static output, **no UI framework**. Interactivity is plain `<script>` in `.astro` files. |
| Styling | Tailwind v4 with tokens in `@theme`. Use Tailwind's scale, never arbitrary values; add a token instead. |
| Colour | The indigo ramp is Flowbite's, copied from the app, so the wordmark matches the logo mark. |
| Fonts | Noto Sans is self-hosted with its licence file (OFL) shipped beside it. |
| Sections | Every content section goes through `Section.astro`. Repeating copy lives in typed constants. |
| Screenshots | Real app component crops, one file per theme. Never fabricated UI or invented numbers. |
| Machine-readable copies | `/llms.txt` and the Markdown copy of the page are generated from the same constants as the page; never hand-edited. |
| Copy | English. **No em dashes in user-facing copy**: readers take them as a sign of machine-written text. |
| Code | No comments. Biome, mirroring the app. |
| Release | Push to `main` deploys to GitHub Pages and tags the version; bump `package.json` for a new release. |
